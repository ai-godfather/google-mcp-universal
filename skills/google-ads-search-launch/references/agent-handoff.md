# Resume and finish another agent's launch run

Use this when taking over a run, continuing an existing review, or receiving a
request to "finish and deploy everything". Continue the main procedure; this
contract keeps a prepared local artifact from being mistaken for a completed launch.

## Bind the work and the permission

Read this skill, then the run's manifest, checkpoint, latest review data and
owner export, cost ledger and receipts. Refresh the account and the exact
existing resources through MCP before deciding what to create. Preserve owner
edits and record the review version and its hash. A local export is a
reference, not a substitute for a later saved version.

Record in the handoff note and the mutation plan:

- run directory, customer and currency, exact product / country / shop scope;
- latest review version and hash, evidence and checkpoint locations;
- existing resources to preserve, proposed resources and per-product holds;
- the owner's actual authorization: text, source and time; the approved daily
  budget and CPC per scope, and whether a new budget is additional or replaces one;
- the separate research cost allowance and the exact permitted landing changes;
- remaining work, verification evidence and concrete conditions for held items.

A drafted message, a proposed budget, another agent's summary or the presence
of this skill is not authorization. If the user asks what to send, write a
draft; do not send it, apply changes, or record it as an owner approval. When
the owner instructs the receiving agent directly, that instruction authorizes
its stated scope. Keep explicit authority already given without asking again,
but never carry a previous run's budget or paid-research allowance into a new run.
If scope, destinations, conversion goals or financial limits differ from the
approval, resolve that difference and continue the independent authorized work.
Routine copy and asset improvements inside an explicitly authorized completion
scope do not need repeated confirmation.

## Complete the remaining work

1. Reconcile every requested row: already deployed, new, alternative or held.
   Reuse exact existing IDs; do not duplicate active ads or pad the cohort with
   products outside the requested selection. Fix only authorized identity or
   landing issues; ownership, routing or currency migrations need their own scope.
2. Complete missing history, Trends, related-query and competitor research.
   Cache first, bounded paid requests only within the actual allowance; save
   attempts, results and costs. Organic SERPs are not competitor ads; missing
   research stays pending, an evidenced empty result is a limitation.
3. Assess grouping and allocations, keeping dedicated budget control. Same
   country does not imply one campaign. Save decisions and exact allocations;
   protect unrelated campaigns, account goals and earlier budgets.
4. Improve native 15/4 copy and complete relevant assets from verified facts.
   Remove filler, respect limits, verify price and pack destinations. Never
   invent discounts, benefits, URLs or keywords for a score.
5. Save the complete review as a new version with the same template views and
   editable fields; merge owner edits on conflict.
6. Execute through the current MCP tools ([delivery-and-verification.md](delivery-and-verification.md)):
   preflight, validate_only, PAUSED creation with durable intents, exact
   conversion goal, assets, group and keyword bids, exact read-back.
7. Inspect each real editor, all Ad Strength categories and inherited assets;
   fix evidenced deficits, save, reopen and record the result. Excellent is a
   goal, not a guarantee or proof of eligibility or performance.
8. If authorized, activate only qualified scope within the approved envelope,
   read back enabled **and** held scope, and record receipts with action time
   separate from observation time ([run-artifacts.md](run-artifacts.md)).

## Finish line

The handoff is complete when each requested item has a reconciled outcome and
the remaining authorized work is done. A CSV, a local HTML page, a successful
API response or a deployment request alone is not completion. If a prerequisite
stays blocked, report partial delivery with its precise resume condition.

Return the review link plus actual campaign, ad group and ad IDs, new and
protected budgets, group and keyword bids, conversion goal, linked assets,
editor scores, moderation, activation times and held items; mark unavailable
proof as unavailable and never fabricate receipts. Do not add monitoring, bid
increases, new tools or wider production changes just to round off the handoff.
Extend a missing MCP capability only when necessary and authorized, following
the plugin's own review, testing and release rules.
